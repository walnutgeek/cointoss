# v0.0.1

First release: a running crypto MVP. One instance sweeps CoinGecko once a day, keeps the
configured universes and daily bars in SQLite, and serves them over JSON-RPC on woodglue.

## New

- **Instrument identity** (`cointoss.instrument`): immutable `{type}.{scope}.{symbol}` ids
  anchored on composite FIGI, source-attributed references and Ticker History; an unresolved
  instrument gets its FIGI attached on a later retry.
- **Series** (`cointoss.series`): time-versioned Universe, Exposure and Covariance Series
  over lythonic value types; Universe entries are stamped with the definition revision.
- **Universes** (`cointoss.universe`): Universe Definitions as revision-logged recipes (rank
  rule, inclusions, exclusions) with pure evaluation, reconciled from config.
- **Risk** (`cointoss.risk`): declared covariance with revision-stamped entries.
- **Prices** (`cointoss.prices`): source-keyed bars with market cap, corporate actions and
  split-aware restatements.
- **Store** (`cointoss.store`): SQLite with pragmas and a schema version; persists
  Instruments, references, Ticker History, Exposure and Covariance entries, Universe
  Definitions, membership intervals, evaluation runs and bars. Reads are point queries;
  writes diff open intervals rather than append whole Series.
- **Sources** (`cointoss.sources`): typed CoinGecko client with rate limiting and daily
  market-chart history, yfinance `get_info` / `get_prices` / `lookup` with generated schema
  models, and an OpenFIGI adapter that takes a Universe of tickers.
- **Ingest** (`cointoss.ingest`): pin a typed ticker or CoinGecko coin to an Instrument, and
  a daily market sweep that records universe membership and the day's bars without
  overwriting bars already written that day.
- **App** (`cointoss.app`): woodglue namespace with the scheduled sweep (`5 0 * * *` UTC by
  default) and a read API, guarded by a sweep lock.
- **CLI** (`cointoss.cli`): `cointoss init`, `sweep` and `status`; `init --systemd` writes a
  user unit, with `--unit`, `--port` and `--schedule` so a second instance can run on the
  same host.

## Changed

- POSIX only: the sweep lock uses `fcntl` and the service runs under systemd. CI covers
  Ubuntu and macOS on Python 3.11-3.13.

## Documentation

## Decisions and tickets

New ADRs:

- [ADR-0001: Unified Instrument abstraction and Trade as System of Record](../adr/0001-unified-instrument-and-trade-sor.md) - a thin stable Instrument and Portfolio as a logical container; its identity part is superseded by ADR-0004.
- [ADR-0002: Exposure Matrix and Universe as Time-Versioned Series](../adr/0002-exposure-matrix-and-universe-as-time-series.md) - universes and exposures as time series; superseded by ADR-0003.
- [ADR-0003: Lythonic Value Types with cointoss Series Wrappers](../adr/0003-lythonic-value-types-with-series-wrappers.md) - lythonic owns the values, cointoss owns time.
- [ADR-0004: Instrument Identity: Immutable Slug Anchored on Composite FIGI](../adr/0004-instrument-identity-slug-and-figi.md) - `{type}.{scope}.{symbol}` ids minted once, FIGI as a first-class reference.
- [ADR-0005: Covariance is Declared, Not Recomputed](../adr/0005-covariance-is-declared-not-recomputed.md) - a covariance for a date is a record, never recomputed.
- [ADR-0006: Cache Universes by Name, Not by Contents](../adr/0006-cache-universes-by-name-not-by-contents.md) - FIGI mappings cached by `(universe_name, as_of)`; the OpenFIGI adapter itself is uncached.
- [ADR-0007: Universe Definition is Separate From Evaluated Membership](../adr/0007-universe-definition-separate-from-evaluated-membership.md) - revision-logged recipes; membership is `(rule + inclusions) - exclusions`.
- [ADR-0008: Rows, Not Blobs: Series Value Types Become Projections of the Store](../adr/0008-rows-not-blobs-value-types-as-projections.md) - point-query reads, interval-diff writes.
- [ADR-0009: Price Storage: Source-Keyed Bars, Adjustment As Fetched](../adr/0009-price-storage-source-keyed-bars.md) - bars stored as fetched, one vintage with `fetched_at`.

Closed tickets:

- #23 init --systemd: name the unit, and set port and schedule, so instances can run side by side
