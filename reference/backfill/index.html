    cointoss.backfill¶

    backfill ¶

    History backfill (#26): fill every date with no stored bar, from CoinGecko and from Yahoo.

    The daily sweep writes one CoinGecko bar per coin per day, and only within the bar window, so a day the machine was down or swept late has no bar, and nothing before the first sweep has one. backfill fills those dates for every Instrument that has ever been a member of any universe (folded through Supersession), from two sources:

    • CoinGecko market_chart over the last days days (90 to 365, the free tier's reach). Each date gets the bar the sweep would have written: the 00:00 UTC price, with volume and market cap. A day whose payload has no point at exactly 00:00 -- today, before CoinGecko publishes it -- is left alone rather than given a later price.
    • Yahoo, for a coin paired with Yahoo: get_prices(period="max"), back to the pair's listing, for dates strictly before today UTC, so no Provisional Bar is written.

    A coin is paired by trying {SYMBOL}-USD (ADR-0009 amendment of 2026-10-30). The pair is accepted when Yahoo's close for session D and CoinGecko's bar stamped D+1, which closes D, differ by less than PAIR_TOLERANCE in median over the last PAIR_SESSIONS sessions both hold. An accepted pair is recorded through the Instrument Registry as an Observation from Yahoo carrying the coin's CoinGecko id and a Yahoo provider id, which adds the Yahoo External Reference and opens a Ticker History record at source yahoo without touching the display symbol or the Price Sources. A rejected pair is logged, stores nothing, and is tried again on the next backfill. A pair whose Yahoo reference another Instrument already holds is rejected too: recording it would be read as evidence the two are one coin, and supersede one of them.

    Only dates with no stored bar from the source are written, so no stored bar is overwritten and no Restatement is filed. Membership is not backfilled: record_membership refuses a date earlier than the latest Evaluation Run.

    Network fetches run outside the sweep lock and each write inside it, through the lock the caller passes: the store is read again for what is missing once the lock is held, so a sweep that wrote today's bar meanwhile keeps it, and a sweep waiting for the lock is held up for one coin's write rather than the whole backfill. CoinGecko is paced by its client's rpm, Yahoo by YAHOO_INTERVAL between requests.

    DEFAULT_DAYS = MARKET_CHART_MAX_DAYS module-attribute ¶

    The CoinGecko window asked for by default: all the free tier serves.

    MIN_DAYS = 90 module-attribute ¶

    The shortest CoinGecko window: below it the API spaces points hourly, off 00:00 UTC.

    PAIR_SESSIONS = 30 module-attribute ¶

    How many of the latest sessions both sources hold a Yahoo pair is checked over.

    PAIR_TOLERANCE = 0.02 module-attribute ¶

    The median relative difference under which a Yahoo pair is the coin CoinGecko names.

    COINGECKO_RPM = 10.0 module-attribute ¶

    Requests per minute to CoinGecko's free tier, which throttles a second immediate call.

    YAHOO_INTERVAL = 2.0 module-attribute ¶

    Seconds between Yahoo requests. yfinance has no limiter of its own.

    BackfillReport ¶

    Bases: BaseModel

    What one backfill did, for a caller to log or report.

    paired are the Instruments whose Yahoo pair was accepted this run; rejected maps an Instrument whose pair was tried and refused, or has no Yahoo history, to why. failed maps an Instrument to a fetch that failed, which leaves its dates for the next run. skipped maps a target that cannot be backfilled -- not a coin, or with no CoinGecko id -- to why.

    median_disagreement(yahoo, coingecko, sessions=PAIR_SESSIONS) ¶

    Median relative difference of two close series over the last sessions both hold.

    Both are keyed by the session closed, so a CoinGecko close is keyed by its stamped date less its Session Offset. Relative to CoinGecko's close. None when fewer sessions overlap.

    >>> d = [date(2026, 10, n) for n in range(1, 5)]
>>> median_disagreement({d[0]: 99.0, d[1]: 110.0, d[2]: 200.0}, {d[0]: 100.0, d[1]: 100.0, d[2]: 100.0}, 3)
0.1
>>> median_disagreement({d[0]: 1.0}, {d[0]: 1.0, d[1]: 1.0}, 2) is None
True

    def median_disagreement(
    yahoo: Mapping[date, float],
    coingecko: Mapping[date, float],
    sessions: int = PAIR_SESSIONS,
) -> float | None:
    """Median relative difference of two close series over the last `sessions` both hold.

    Both are keyed by the session closed, so a CoinGecko close is keyed by its stamped date
    less its Session Offset. Relative to CoinGecko's close. None when fewer sessions overlap.

    >>> d = [date(2026, 10, n) for n in range(1, 5)]
    >>> median_disagreement({d[0]: 99.0, d[1]: 110.0, d[2]: 200.0}, {d[0]: 100.0, d[1]: 100.0, d[2]: 100.0}, 3)
    0.1
    >>> median_disagreement({d[0]: 1.0}, {d[0]: 1.0, d[1]: 1.0}, 2) is None
    True
    """
    both = sorted(set(yahoo) & set(coingecko))[-sessions:]
    if len(both) < sessions:
        return None
    return statistics.median(abs(yahoo[d] - coingecko[d]) / coingecko[d] for d in both)

    async def backfill(
    store: Store,
    at: datetime,
    *,
    days: int = DEFAULT_DAYS,
    coingecko: CoinGeckoClient | None = None,
    lock: WriteLock | None = None,
) -> BackfillReport:
    """Fill every missing CoinGecko and Yahoo date for every Instrument ever a member.

    `at` is the moment of the run: its UTC date is today, the first date no Yahoo bar is written
    for, and it stamps the bars' `fetched_at`. `lock` is entered around each write. Raises
    `ValueError` for a `days` outside `MIN_DAYS` to `MARKET_CHART_MAX_DAYS`, before anything
    is fetched. See the module docstring for what is written and how a coin is paired.
    """
    if not MIN_DAYS <= days <= MARKET_CHART_MAX_DAYS:
        raise ValueError(f"days={days} is outside {MIN_DAYS}..{MARKET_CHART_MAX_DAYS}")
    moment = as_utc(at)
    run = _Run(
        store,
        moment,
        coingecko or CoinGeckoClient(rpm=COINGECKO_RPM),
        lock or nullcontext,
    )
    targets = _targets(store)
    for instrument in targets:
        await run.instrument(instrument, days)
    log.info(
        "backfill %s: %d targets, %d CoinGecko bars, %d Yahoo bars, paired %s, rejected %d",
        moment.date(),
        len(targets),
        run.coingecko_bars,
        run.yahoo_bars,
        sorted(run.paired) or "none",
        len(run.rejected),
    )
    return BackfillReport(
        at=moment,
        days=days,
        targets=len(targets),
        coingecko_bars=run.coingecko_bars,
        yahoo_bars=run.yahoo_bars,
        paired=run.paired,
        rejected=run.rejected,
        failed=run.failed,
        skipped=run.skipped,
    )
